# P2 Site Generation Specification

## Purpose

Generate an Eclipse P2 repository (update site) that wraps `io.swagger:swagger-core:1.5.24` and its transitive dependencies as OSGi-compatible bundles, packaged as a distributable ZIP archive.

## Architecture

The build pipeline is a single-module Maven project with no Java source code. It relies on three key plugins executed during the `package` phase:

- **p2-maven-plugin** — resolves `swagger-core:1.5.24` from Maven Central, wraps all JARs as OSGi bundles, and generates P2 metadata (`content.xml`, `artifacts.xml`) at `target/repository/`
- **maven-assembly-plugin** — packages the `target/repository/` directory into a ZIP with classifier `site` (descriptor: `src/assembly/assembly.xml`)
- **flatten-maven-plugin** — resolves the CI-friendly `${revision}` property into a concrete version in the published POM

Deployment is handled by profile-activated plugins:
- **wagon-maven-plugin** (WebDAV) — uploads the P2 site to JUDO Nexus at a versioned path
- **nexus-staging-maven-plugin** — stages and releases to Maven Central via Sonatype OSSRH
- **sign-maven-plugin** — GPG-signs artifacts before deployment

## Requirements

### Requirement: P2 repository generation

The build SHALL produce a valid Eclipse P2 repository containing OSGi bundles for `io.swagger:swagger-core:1.5.24` and all its transitive dependencies.

#### Scenario: Successful P2 site generation
- **GIVEN** a clean workspace with Maven 3.9.4 and Java 21
- **WHEN** `./mvnw clean package` is executed
- **THEN** `target/repository/` contains `content.xml`, `artifacts.xml`, and `plugins/` directory with OSGi bundles
- **THEN** source bundles are included (configuration: `<source>true</source>`)
- **THEN** the repository is compressed (configuration: `<compressSite>true</compressSite>`)

### Requirement: ZIP archive packaging

The build SHALL package the P2 repository as a ZIP file suitable for offline distribution.

#### Scenario: ZIP assembly
- **GIVEN** the `target/repository/` directory has been generated by p2-maven-plugin
- **WHEN** the `maven-assembly-plugin` executes during `package` phase
- **THEN** a file `target/swagger-p2-<version>-site.zip` is created
- **THEN** the ZIP root contains the repository contents directly (no base directory wrapper)

### Requirement: CI-friendly version resolution

The project SHALL use the `${revision}` property for version management, resolved to a concrete value in published artifacts.

#### Scenario: Flatten POM for publishing
- **GIVEN** `pom.xml` declares `<version>${revision}</version>` with `<revision>1.0.4-SNAPSHOT</revision>`
- **WHEN** the `flatten-maven-plugin` executes during `process-resources` phase
- **THEN** `.flattened-pom.xml` is generated with the resolved version `1.0.4-SNAPSHOT`
- **THEN** the flattened POM is used for install and deploy instead of the original

### Requirement: JUDO Nexus deployment

The build SHALL support deploying Maven artifacts and the P2 site to JUDO Nexus when the appropriate profiles are active.

#### Scenario: Maven artifact deployment
- **GIVEN** profile `release-judong` is active and Nexus credentials are configured
- **WHEN** `./mvnw deploy -Prelease-judong` is executed
- **THEN** artifacts are uploaded to `https://nexus.judo.technology/repository/maven-judong-snapshots/`

#### Scenario: P2 site deployment via WebDAV
- **GIVEN** profile `release-p2-judong` is active and Nexus credentials are configured
- **WHEN** `./mvnw deploy -Prelease-p2-judong` is executed
- **THEN** the contents of `target/repository/` are uploaded via WebDAV to `dav:https://nexus.judo.technology/repository/p2-judong/swagger-p2/<version>/`

### Requirement: Maven Central deployment

The build SHALL support deploying signed artifacts to Maven Central via Sonatype OSSRH.

#### Scenario: Central release with signing
- **GIVEN** profiles `release-central` and `sign-artifacts` are active
- **GIVEN** GPG keys and Sonatype OSSRH credentials are configured
- **WHEN** `./mvnw deploy -Prelease-central,sign-artifacts` is executed
- **THEN** artifacts are GPG-signed and staged to `https://oss.sonatype.org/`
- **THEN** the staging repository is automatically closed and released (timeout: 15 minutes)

### Requirement: Artifact signing

The build SHALL support GPG signing of all artifacts when the `sign-artifacts` profile is active.

#### Scenario: GPG signing
- **GIVEN** profile `sign-artifacts` is active and GPG keys are available
- **WHEN** the `sign-maven-plugin` executes
- **THEN** all artifacts (POM, ZIP, JAR) have corresponding `.asc` signature files
